THE APPROACH

EXTEND, DON’T REWRITE

We used FitArena as the base, gave Claude the three stores’ products.json files and followed four steps.

01

Pick the base

FitArena provides the whole technical stack: React 18 + Vite, Redux Toolkit, React Router v6, the service layer, cart, checkout, orders, admin and tests.

02

Merge the catalogues

FitArena, StrideHub and MediKart JSON go through merge-products.mjs and come out as one movewell-products.json. The source files are not modified.

03

Preserve FitArena

We kept the existing ids, routes, cart, checkout and storage keys, so carts and orders already saved in shoppers’ browsers still work.

04

Transform to MoveWell

We added three categories, a new homepage, and two features that span categories: Fitness Goals and MoveWell Kits.

STEP 2 · DATA

ONE UNIFIED CATALOGUE

All three files already used the same field names. The differences were in the values: id format, what category meant, spec key casing and missing images.

Store MoveWell category Products Original ids MoveWell ids Original “category” meant
FitArena sports 62 1–62 unchanged Cricket, Football, Badminton, Gym, Yoga, Activewear
StrideHub footwear 50 "prod-001"… 1000 + n Sports, Casual, Formal shoes, Sandals, Heels, Kids
MediKart health 66 "p-001"… 2000 + n Vitamins, Pain relief, Diabetes care, Devices, First aid, Baby care
MoveWell 3 categories 178 unique integers, checked by the script moved to subcategory

Traceability: every record keeps source and sourceId, so each MoveWell product can be traced back to its original store. To rebuild the catalogue, run node scripts/merge-products.mjs.

STEP 2 · SCHEMA

THE UNIFIED PRODUCT

{ id: 1001, // integer, unique title: "RunPro Elite", category: "footwear", // sports|footwear|health subcategory: "Sports shoes", brand: "RunFast", price: 5999, // rupees discountPercentage: 15, rating: 4.8, stock: 42, specs: { Size, Colour, Material, … }, goals: ["running"], // running|gym|yoga thumbnail, images, source: "StrideHub", sourceId: "prod-001" }
  • Kept FitArena’s field names. All three stores already shared them, so renaming would have touched almost every component for no gain.
  • MRP is calculated, not stored. originalPrice() computes it, so price and MRP always come from one value.
  • Spec keys are normalised. The first letter is upper-cased (colour → Colour), values are untouched and empty values are dropped.
  • Goals come from the data. They are read from existing subcategories, specs and descriptions, and medicines are never tagged.
CONFLICTS.MD

CONFLICTS & RESOLUTIONS

Conflict What broke Resolution
String vs integer ids FitArena parses ids with Number(id) everywhere, so ids like “prod-001” were rejected Per-store integer ranges (1000+, 2000+); the script fails on any id clash
“category” meant 3 things Each store used it for its own types; old links used ?category=Cricket category is now the department and the old value moved to subcategory; old links still work
Copied MediKart specs Ibuprofen listed “Composition: Paracetamol”, which is a wrong medical fact Specs that are identical across a whole category move to sourceCategorySpecs and are hidden
Missing image files The Footwear and Health image files were not supplied The script generates an SVG card for each product; FitArena’s photos are unchanged
Saved browser data Old admin records, the nextId counter and the fitarena: storage prefix Old records are read into the new schema, new ids skip used ranges and storage keys are kept
Missing discount field & old tests 22 products had no discount field, and tests expected “Cricket” as a category Missing discounts stored as 0; tests updated and new tests added

No conflict: cart, checkout, orders, reviews, wishlist, pricing (all in rupees), field names and routing.

STEP 3 · PRESERVE

FITARENA, STILL WORKING

Kept as-is

  • Checkout: address → payment → review, with stock and price re-checked
  • Orders with the 60-second cancel, reviews, wishlist and addresses
  • Delivery PIN, theme, shopper / store manager switch, cross-tab sync
  • Routes: /, /products, cart, checkout, account, admin
  • FitArena ids 1–62 and the fitarena: storage keys, so saved carts survive

Extended, not duplicated

  • One productsService with new subcategory and goal filters
  • One cartSlice for every category, plus addKitToCart
  • One productsSlice plus a new profileSlice for the fitness goal
  • Only 2 new routes: /goals and /kits (lazy-loaded)
  • Admin form: a Category select, a Type field and Fitness-goal checkboxes

No second cart and no per-category routes. Categories reuse /products?category=sports|footwear|health, so filters, sorting and paging keep working unchanged.

STEP 4 · TRANSFORM

BECOMING MOVEWELL

Sports · FitArena

62 products

Cricket, Football, Badminton, Gym equipment, Yoga, Activewear

Footwear · StrideHub

50 products

Sports, Casual, Formal shoes, Sandals, Heels, Kids shoes

Health · MediKart

66 products

Vitamins, Pain relief, Diabetes care, Devices, First aid, Baby care

New homepage

“Move better. Live better.” hero, shop-by-category cards, a goal picker, featured products from all three categories, kits, and a Why MoveWell section.

Fitness Goals

Running, Gym or Yoga. The goal is saved in profileSlice and synced across tabs. Recommendations alternate Sports, Footwear and Health so no store dominates.

MoveWell Kits

Marathon, Gym and Yoga starter kits. Kit slots are filled by department and goal (not fixed ids) with the best-rated in-stock product. A kit adds normal lines to the cart.

Also: the header, catalogue filters, product cards, product details and cart are all category-aware. Health products carry a “not medical advice” note, and the design is re-themed with a deep-teal brand and one colour per category.
